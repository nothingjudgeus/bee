# 部署与迁移

## GitHub 网页上传

1. 解压压缩包，进入 bee-study 文件夹。
2. 在 GitHub 创建自己的仓库。选择公开还是私有由你决定；私有仓库的 Pages 可用性取决于账户方案。
3. Add file → Upload files，上传项目内容到仓库根目录。点开仓库核对 README.md、dist、scripts 和 .github 都在根目录；压缩包本身不是可部署的网站源码。
4. 如果系统隐藏 .github，使用 Git 命令上传最可靠。Windows 文件资源管理器中可开启隐藏文件显示。网站部署配置必须位于 .github/workflows/deploy.yml。
5. Settings → Pages → Build and deployment → Source：GitHub Actions。
6. 在 Actions 中手动运行 Publish Bee website，或修改 README 提交触发一次 main 推送。成功后使用 Pages 页面显示的实际网址。

## Git 命令上传

已安装 Git，并在终端进入解压后的项目根目录。以下每行分别执行，仓库地址换成你自己创建的仓库：

```sh
git init
git add .
git commit -m "Initial Bee website"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/YOUR_REPOSITORY.git
git push -u origin main
```

仓库已经有 README 或其他提交时，先 clone 该仓库，再把本包内容复制进去提交，避免强行覆盖历史。认证使用 GitHub 官方登录或凭据管理器，不要把令牌写入源码。

日后更新：

```sh
node scripts/validate.mjs
git add .
git commit -m "Update Bee website"
git push
```

## 其他托管

Cloudflare Pages：连接仓库，框架选 None，无构建命令，发布目录 dist。其他静态托管同理。自己的 Nginx/Apache：把 dist 的内容放到网站根目录，配置 HTTPS。本站使用 hash 路由，通常无需单页应用的路径重写。

本地 serve.py 用于预览，不是公开生产服务器。没有数据库和登录后台可迁移。博客公开发布通过修改文件、Git 提交与重新部署完成。

## 绑定自定义域名

按托管平台生成的 DNS 提示操作。GitHub Pages 在 Settings → Pages 的 Custom domain 设置；必要时新增 dist/CNAME，内容仅为你的实际域名。当前包不含虚构域名或绑定。

## 访问与费用

代码包不包含 ChatGPT 登录或原站的访问控制。GitHub Pages 发布的网页可公开访问；不要把个人草稿、私人数据或密钥放入 dist。原站的学习记录不会自动迁入新域名，先备份再导入。

静态站无数据库月费；域名、托管流量和账户限制按服务商实际方案计。这里没有内置付费 API；音乐由浏览器合成。
