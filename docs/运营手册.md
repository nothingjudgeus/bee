# 中文运营手册

## 日常发布文章

1. 启动本地网站，点击页脚“写一页”，填写标题、分类与正文，用空行分段。
2. 保存，预览文章，再导出文章备份。保存草稿只影响当前浏览器，不会立即公开。
3. 在项目根目录打开终端，执行 `python3 scripts/publish_posts.py "备份文件的完整路径.json"`。Windows 可用 `py -3` 代替 `python3`。
4. 脚本按文章 id 合并，同 id 更新，不同 id 保留。修改后的正式内容在 `dist/content/posts.json`。
5. 运行 `node scripts/validate.mjs`，本地预览，确认后提交到 GitHub。Actions 成功后文章会出现在所有访客的页面中。

也可直接修改 posts.json。每条文章包含 id、title、body、date、category、summary；body 是纯文本，用 `\n\n` 表示段落。保持 id 稳定。暂不支持在正式文章正文中嵌入 HTML，防止把输入内容当脚本运行；需要图文自由排版可编辑 site.js 的文章模板。

删除正式文章：先备份 posts.json，删除对应对象并重新发布。只在浏览器删除草稿不会删除正式文章。同 id 本地草稿可能覆盖本机看到的正式稿，发布后可以删除该本地草稿。

## 修改题库与方法

`dist/atlas-data.js` 中 window.ATLAS_DATA 包含 modules、nodes、exercises 三个数组。

- modules：章节的 id、title、subtitle、caption 等。
- nodes：知识点 id、module、title、html、exerciseIds。html 是完整知识说明。
- exercises：题号 id、module、title、source、label、method、questionHtml、solutionHtml、nodeIds、配图路径等。

最稳妥的做法是复制一条同类条目作为结构样本，再改内容。不要重复 id。题目与节点相互关联时同时更新 nodeIds 与 exerciseIds；新配图放入 assets，并使用 assets/文件名 的相对路径。公式沿用已有题目的 MathML/HTML 写法；网站没有新增可在线编译任意 LaTeX 的服务。新增题的训练逻辑需要同步更新 atlas.js 中的题型映射和方案，不能只复制题干就默认训练适配。

网页里的“编辑节点”修改存在浏览器，只对当前访客可见。若想让所有访客看到，需要将修改写回 atlas-data.js 或 atlas.js 的默认布局，再提交源码。

## 学习记录备份

- 主站“备份与设置”可导出完整备份；数学图谱工具栏也可导出数学记录。
- 换设备或换域名前，先从原站导出，在新站导入。域名、端口与浏览器不同，各自的本地存储互不共享。
- 备份可能包括个人笔记、文章草稿和学习情况，保存到自己的文件夹；不要提交进公开 GitHub 仓库。
- 正式文章脚本仅提取文章，不会把整份学习备份公开。

## 每次更新

先备份 → 修改源码 → 运行检查 → 本地看首页、题目解析、图谱和训练 → 推送 → 在 Actions 查看结果。GitHub 编辑单个文件时也可使用网页铅笔按钮，但不要漏传图片。

## 回滚与维护

GitHub 提交历史可以恢复旧文件；批量回滚建议使用 `git revert 提交SHA` 后推送。不要用 reset --hard 或强制推送处理不熟悉的历史。部署失败时保留失败日志，先修复脚本报告的路径或 JSON 语法错误，再提交。

每月手工导出个人记录，检查图片能否打开；收到数学纠错时保留题目来源和改动记录。依赖仅为 GitHub 官方 Actions，在更新其主版本前查看官方迁移说明。
